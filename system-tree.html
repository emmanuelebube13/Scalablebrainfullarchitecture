3. Scalability Assessment & Bottlenecks

Active Constraint

SQLite Write-Lock Serialization

ams.db uses SQLite WAL mode. While WAL permits infinite concurrent readers, writers serialize with an exclusive lock. If telemetry dashboard polling coincides with a high-volatility 10-signal burst from System 1, lock contention can cause transient 5-second delays.

Architectural Solution

Local-First Read Replicas & PostgreSQL

The Layer 4 Telemetry server connects to SQLite using ?mode=ro&immutable=1 or queries the PostgreSQL replica directly. System 3 Guardian writes uninterrupted to ams.db with dedicated 5000ms busy timeouts.
